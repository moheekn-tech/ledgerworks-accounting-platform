# Public vendor contract evidence

Retrieved and inspected on 2026-10-14. The YAML files in vendor-schemas are Zoho's published OpenAPI downloads, not copies of a private database. They provide request/response structures; they do not prove account-specific behavior. Contract tests validate selected write bodies and emulate source readback. Real customer acceptance remains separate.

Primary Zoho sources: [chart of accounts and GL transactions](https://www.zoho.com/books/api/v3/chart-of-accounts/), [bills](https://www.zoho.com/books/api/v3/bills/), [invoices](https://www.zoho.com/books/api/v3/invoices/), [vendor payments](https://www.zoho.com/books/api/v3/vendor-payments/), [customer payments](https://www.zoho.com/books/api/v3/customer-payments/), [bank transactions and categorization](https://www.zoho.com/books/api/v3/bank-transactions/), [expenses](https://www.zoho.com/books/api/v3/expenses/), [contacts](https://www.zoho.com/books/api/v3/contacts/) and [journals](https://www.zoho.com/books/api/v3/journals/). Credit-note/vendor-credit schemas are retained for subsequent coverage; these write workflows are not implemented here. Refresh public schemas with scripts/fetch-vendor-schemas.mjs and inspect field requirements with scripts/inspect-schemas.mjs.

Tally reconstruction uses its [official XML integration reference](https://help.tallysolutions.com/developer-reference/integration-capabilities/references/integration-using-xml-interface/). Internal proprietary database layouts are not used. Tally exposes a local company-scoped XML interface; the included gateway transports that interface from the customer's machine.

Production orchestration follows the [official Temporal PostgreSQL Compose example](https://github.com/temporalio/docker-compose/blob/main/docker-compose-postgres.yml), [published example versions](https://github.com/temporalio/docker-compose/blob/main/.env), and [official container entrypoint](https://github.com/temporalio/docker-builds/blob/main/docker/entrypoint.sh). The local official Temporal CLI runtime was executed; the production Docker package was not run on this machine.

The exercised local classifier is [Xenova/distilbert-base-uncased-mnli](https://huggingface.co/Xenova/distilbert-base-uncased-mnli). Model results and accounting accuracy remain different claims; representative accountant-labelled evaluation is required.

Statutory preparation references the [Income Tax portal's Form 140 guidance](https://www.incometax.gov.in/iec/foportal/newformpage/forms/form140-um), [GST developer portal](https://developer.gst.gov.in/apiportal/taxpayer/returns2), and [official notified e-invoice schema](https://einvoice6.gst.gov.in/content/notified-e-invoice-schema/). Current schema/utility files must be supplied through the official/provider workflow. Prepared workpapers are not government acceptance evidence.
